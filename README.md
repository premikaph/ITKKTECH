# ITKKTECH
สำหรับรายวิชาการพัฒนาระบบร่วมกันด้วยแพลตฟอร์ม
---------------------------------------------
🚀 ขั้นตอนการทำงานร่วมกันบน GitHub
1. การดึงโปรเจกต์มาที่เครื่องเรา (Git Clone)
ก่อนจะเริ่มงาน เราต้องไป "ก๊อปปี้" โปรเจกต์จากส่วนกลาง (Remote Repository) มาไว้ในคอมพิวเตอร์ของเราก่อน

คำสั่ง: git clone <URL ของโปรเจกต์>

อุปมา: เหมือนการไปถ่ายเอกสารจากต้นฉบับที่ห้องสมุดมาไว้ที่โต๊ะเขียนหนังสือของเราเอง

2. การสร้างพื้นที่ทำงานของตัวเอง (Branching)
สำคัญมาก: เราจะไม่แก้ที่ตัวหลัก (main) โดยตรง เพราะถ้าโค้ดพัง ทุกคนจะพังหมด เราจึงต้องแยก "กิ่ง" ออกมาทำ

คำสั่ง: git checkout -b <ชื่อกิ่งใหม่>

ทำไมต้องทำ: เพื่อให้เราลองผิดลองถูกได้เต็มที่ โดยไม่กระทบกับงานของเพื่อน

3. การบันทึกการเปลี่ยนแปลง (Add & Commit)
เมื่อเราแก้โค้ดหรือเพิ่มไฟล์เสร็จแล้ว เราต้องบอก Git ให้บันทึกความคืบหน้า

Add: เลือกไฟล์ที่จะบันทึก (git add .)

Commit: เขียนโน้ตกำกับว่าเราทำอะไรไป (git commit -m "เพิ่มปุ่มสีแดง")

Tip: สอนให้นักเรียนเขียน Commit Message ให้คนอื่นอ่านรู้เรื่องเสมอ

4. การส่งงานขึ้นไปบน GitHub (Push)
ตอนนี้งานถูกบันทึกแค่ใน "คอมพิวเตอร์เรา" เท่านั้น เพื่อนยังไม่เห็น เราต้องดันมันขึ้นไปบนเมฆ (GitHub)

คำสั่ง: git push origin <ชื่อกิ่งของเรา>

5. การขอส่งงานเข้าส่วนกลาง (Pull Request - PR)
นี่คือขั้นตอนที่ GitHub ต่างจาก Git ธรรมดา เมื่อเรา Push งานขึ้นไปแล้ว เราต้องกดปุ่ม "Compare & pull request" บนหน้าเว็บ GitHub

มันคือการบอกว่า: "หัวหน้าครับ/เพื่อนครับ ช่วยตรวจงานฉันหน่อย ถ้าโอเคแล้วช่วยเอาไปรวมกับโปรเจกต์หลักที"

Code Review: เพื่อนๆ สามารถมาคอมเมนต์ติชมโค้ดเราได้ในขั้นตอนนี้เลย

6. การอัปเดตงานเพื่อนมาใส่เครื่องเรา (Pull)
ในขณะที่เราทำ เพื่อนคนอื่นก็ส่งงานเข้าส่วนกลางเหมือนกัน เราจึงต้องดึงงานล่าสุดมาอัปเดตเสมอ

คำสั่ง: git pull origin main

ทำไมต้องทำ: เพื่อป้องกันอาการ "โค้ดตีกัน" (Merge Conflict)
